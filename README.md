# 快传

快传是一个可自行部署的文件与文字分享服务。

使用者通过网页选择文件或输入文字，即可生成一条分享链接和一个四位密码。接收方打开链接、输入密码，即可下载文件或查看文字。

## 功能

- **文件分享**：支持多选文件与整个文件夹，接收端保留原有目录结构。
- **文字分享**：接收方可直接复制，或下载为 `.txt` 文件。
- **两种传输方式**：直接传输与先上传到服务器，详见「传输方式」。
- **断点续传**：先上传到服务器时，上传和下载都可从已完成的部分接着进行，网络中断后无需从头开始。
- **暂停与停止**：传输过程中可暂停、继续或停止。暂停后再次继续会从断点接着传输；停止会清理未完成的部分，已经完成的文件仍然保留。
- **密码保护**：四位密码，字符取自大写字母、小写字母与数字，区分大小写。
- **可选限制**：阅后即焚、限制被取走次数、随时作废链接。
- **二维码**：便于手机扫码打开。

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 原生部署 | Node.js 24 或更高版本 |
| 容器部署 | Docker 与 Docker Compose |
| 浏览器 | Chrome、Edge、Firefox、Safari 等现代浏览器 |

## 部署

### 方式一：直接运行

```bash
./scripts/pnpm-local.sh install
cp .env.example .env
pnpm start
```

Windows 系统：

```cmd
scripts\pnpm-local.cmd install
copy .env.example .env
pnpm start
```

服务默认监听 `7654` 端口。在本机访问 <http://localhost:7654>；其他设备访问时，请使用该服务器可访问的地址，例如 `http://<服务器地址>:7654`。分享链接与二维码会按打开页面时的浏览器地址生成，不需要在配置中填写地址；如果要发给其他设备，请先用该设备能访问的地址打开本页。

### 方式二：Docker

```bash
cp docker-compose.example.yml docker-compose.yml
docker compose up -d
```

服务地址与上一种方式相同。数据保存在名为 `kuaichuan-data` 的卷中：执行 `docker compose down` 仅停止服务并保留数据，执行 `docker compose down -v` 会同时删除数据。

如需将数据存放在宿主机目录，请将 `docker-compose.yml` 中的卷映射改为 `./data:/data`。容器启动时会自动把该目录的属主调整为容器内的运行用户，不需要在宿主机执行 `chown` 或 `sudo`；数据目录可直接查看和备份。Docker 部署全程不需要 `sudo`。

仓库在打 tag 时会自动构建镜像并发布到 GitHub Container Registry，也可以不本地构建，直接拉取使用：

```bash
docker pull ghcr.io/cyilin36/kuaichuan:latest
```

使用发布镜像时，删除 `docker-compose.yml` 中的 `build: .`，并将 `image` 改为 `ghcr.io/cyilin36/kuaichuan:latest`。`latest` 跟随最新稳定版，每个版本另有 `x.y.z` 标签；预发布版只有版本号标签，不包含 `latest`。若提示未授权，请先执行 `docker login ghcr.io`。

### 方式三：作为系统服务运行

仓库提供 systemd 服务模板 [deploy/kuaichuan.service](deploy/kuaichuan.service)。请先根据实际路径修改模板中的 `WorkingDirectory` 与 `ExecStart`，再复制到 `/etc/systemd/system/` 并执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now kuaichuan
```

## 使用方法

1. 打开首页，选择「文件」或「文字」。
2. 选择传输方式：「直接传输」或「先上传到服务器」。
3. 按需设置密码保护、被取走次数上限与阅后即焚；选择「先上传到服务器」时还可设置有效期。
4. 点击「生成链接」，将链接或二维码发送给接收方。
5. 接收方打开链接，输入密码后即可下载或查看。
6. 传输过程中可使用「暂停」「继续」「停止」控制进度。

启用密码保护时，四位密码**仅在创建分享时显示一次**，请及时记录。已创建的分享可在 `/manage` 页面查看并作废。

暂停后再点「继续」，会从已经完成的部分接着传输；如果网络中断，页面也会自动尝试从断点重试。停止会清理未完成的部分，已上传或已下载完成的文件仍然保留。以上控制只在当前页面内有效，刷新页面后需要重新开始。

## 传输方式

| 方式 | 说明 |
| --- | --- |
| 直接传输 | 文件在发送方与接收方浏览器之间直接传输，不写入服务器磁盘。发送方须保持页面打开，页面关闭后链接随即失效，因此不需要设置有效期。传输中可以暂停、继续或停止；暂停只在当前连接内有效，连接断开后需要重新接收。 |
| 先上传到服务器 | 文件保存至服务器，默认保留 24 小时，上传完成后发送方可关闭页面。上传和下载都支持暂停、继续与断点续传。 |

当两台设备无法直接连接时，系统会自动改为经服务器转交。该过程不会把内容保存到服务器，页面会提示当前使用的传输方式。

## 配置

配置文件为项目根目录下的 `.env`，可从 `.env.example` 复制后修改。Docker 部署时，请在 `docker-compose.yml` 的 `environment` 中配置。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_NAME` | `快传` | 页面标题与显示名称 |
| `PORT` | `7654` | 监听端口 |
| `DATA_DIR` | `./data` | 数据目录，存放数据库、已上传的文件与密钥 |
| `DEFAULT_TTL_HOURS` | `24` | 新建「先上传到服务器」分享的默认保留时长（小时） |
| `MAX_TTL_HOURS` | `168` | 「先上传到服务器」可选的最长保留时长（小时）；同时作为直接传输分享记录的最长清理期 |
| `MAX_FILE_BYTES` | `2147483648` | 上传到服务器时的单个文件上限（字节），默认 2GB；`0` 表示不限制 |
| `MAX_P2P_FILE_BYTES` | `0` | 直接传输时的单个文件上限（字节），默认 `0` 表示不限制 |
| `MAX_TEXT_BYTES` | `1048576` | 单条文字上限（字节），默认 1MB |
| `MAX_TOTAL_BYTES` | `21474836480` | 服务器上保存的文件总量上限（字节），默认 20GB；`0` 表示不限制 |
| `RELAY_ENABLED` | `1` | 无法直接连接时是否允许经服务器转交；`0` 表示关闭 |
| `STUN_URLS` | 公共 STUN | 建立直接连接时使用的 STUN 服务器，逗号分隔；留空表示仅尝试同一网络内的直接连接 |
| `TOKEN_SECRET` | 空 | 令牌签名密钥；留空则首次启动时自动生成并保存至 `data/secret.key` |
| `LOG_LEVEL` | `info` | 日志级别：`debug`、`info`、`warn`、`error` |

完整配置项及逐项说明见 [.env.example](.env.example)。
